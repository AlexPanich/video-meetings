# Plan: Локальный LLM SDK, совместимый с Claude Agent SDK, и саммари встречи

**PRD:** @docs/prd-local-llm-sdk.md
**Дата:** 2026-11-12

## Правило тестов (test-first)

В каждой фазе первой задачей пишутся тесты на поведение фазы, и их запускают до реализации: они должны быть **красными**. Затем реализуется фаза, и в конце те же тесты должны стать **зелёными**. Фаза не считается готовой, пока эти тесты не позеленели и не проходят `pnpm build`, `pnpm lint`, `pnpm test`, `pnpm test:e2e` и `pnpm --filter web typecheck`.

- SDK-фазы (1–4): unit-тесты в `packages/llm-sdk` на мок-транспорте Ollama (без сети, их запускает pre-commit hook) и контрактный набор. Контрактный набор запускается вручную по флагу: против живой Ollama + Qwen и против `@anthropic-ai/claude-agent-sdk` с `ANTHROPIC_API_KEY`. Каждая фаза добавляет в него свои сценарии.
- API-фазы (5, 7): e2e-тесты в `apps/api/test/*.e2e-spec.ts` (реальная БД, мок-LLM и мок-Whisper) и unit-тесты handler'ов.
- UI-фаза (6): тесты web на Vitest + Testing Library.

## Решения, принятые при планировании

- Фасад — отдельный workspace-пакет `packages/llm` (`@video-meetings/llm`), первый из двух вариантов PRD. Код фич импортирует только его.
- Совместимость типов проверяет отдельный тестовый файл с кодом фичи. Он проходит `tsc` дважды: с фасадом, который указывает на `@video-meetings/llm-sdk`, и с фасадом, который указывает на `@anthropic-ai/claude-agent-sdk`. Каждая SDK-фаза дописывает в этот файл свои возможности.

## Порядок и зависимости

Фазы 1–4 собирают SDK и фасад. После каждой из них SDK работает, но умеет меньше. Фаза 5 (саммари по текстовым файлам, API) использует инструменты из фазы 2 и `outputFormat` из фазы 3. Фаза 6 (UI) опирается на API фазы 5. Фаза 7 добавляет транскрибацию к уже работающему саммари. UI фазы 6 уже показывает статус «Транскрибация», поэтому отдельная UI-фаза для неё не нужна.

## Фазы реализации

### Фаза 1: Tracer Bullet — `query()` с простым ответом через Ollama и фасад по `LLM_PROVIDER`

**Цель:** Минимальный путь: код фичи вызывает `query({ prompt, options })` из фасада и получает ответ Qwen с машины в LAN. При `LLM_PROVIDER=anthropic` тот же код идёт в Claude Agent SDK.
**Затрагивает:** backend (новые пакеты `packages/llm-sdk`, `packages/llm`)
**Задачи:**

- [ ] Написать тесты и убедиться, что они красные. Unit на мок-транспорте: поток сообщений `system/init` (`session_id`, `model`, `tools`) → `assistant` (блок `text`) → `result/success` (`result`, `num_turns`, `duration_ms`, `usage`, `total_cost_usd = 0`, `session_id`); `prompt` строкой и как `AsyncIterable<SDKUserMessage>`; недоступная Ollama и таймаут запроса дают понятную ошибку, а не зависание; при `LLM_PROVIDER=local` ни одного запроса на домены Anthropic (тест с перехватом сети). Контрактный сценарий «простой ответ». Файл совместимости типов с `query`
- [ ] Пакет `packages/llm-sdk`: ESM, `packages/*` в `pnpm-workspace.yaml`, скрипты `build`/`lint`/`test`, которые запускаются из корня. Типы `SDKMessage`, `Query`, `Options` повторяют оригинал. Опорная версия `@anthropic-ai/claude-agent-sdk` зафиксирована в `package.json`
- [ ] Транспорт Ollama (`OLLAMA_URL`, `OLLAMA_MODEL`, `OLLAMA_NUM_CTX`, таймаут запроса из env) и `query()` для одного хода: `model`, `systemPrompt`, объект `Query` как `AsyncGenerator<SDKMessage>`
- [ ] Фасад `packages/llm` (`@video-meetings/llm`): выбирает реализацию по `LLM_PROVIDER` (`local` | `anthropic`) и реэкспортирует единый набор функций и типов. Переключение — только через env
- [ ] Обновить `.env.example` (значения из PRD и `ANTHROPIC_API_KEY`), `CLAUDE.md` (новые пакеты, команды, env), начать README пакета; тесты первой задачи зелёные

**Когда готова:** `pnpm build`, `pnpm lint` и `pnpm test` проходят из корня. Код с `query()` из фасада получает ответ Qwen при `LLM_PROVIDER=local` и ответ Claude при `LLM_PROVIDER=anthropic` без правки кода. Тест с перехватом сети подтверждает, что в режиме `local` к Anthropic не уходит ни одного запроса.

### Фаза 2: Инструменты, агентный цикл и права

**Цель:** Модель вызывает SDK-инструменты, SDK выполняет их и возвращает результат модели, пока не будет финального ответа или `maxTurns`. Права и хуки управляют доступом к инструментам.
**Затрагивает:** backend (`packages/llm-sdk`)
**Задачи:**

- [ ] Написать тесты и убедиться, что они красные. Unit на мок-транспорте: вызов SDK-инструмента и `tool_result` в сообщении `user`, имена `mcp__<server>__<tool>`, `maxTurns` → `error_max_turns`, `allowedTools`/`disallowedTools`, `canUseTool` с deny, `permissionMode` (`default`, `acceptEdits`, `bypassPermissions`, `plan`), хуки `PreToolUse` (deny, изменение ввода), `PostToolUse`, `UserPromptSubmit`, `Stop`, `SessionStart`, `SessionEnd` с matcher, усечение старых результатов инструментов при приближении к `num_ctx`. Контрактные сценарии: вызов инструмента, `error_max_turns`, deny в `PreToolUse`, deny в `canUseTool`. В файл совместимости добавить `tool` и `createSdkMcpServer`
- [ ] `tool(name, description, zodSchema, handler)` и `createSdkMcpServer({ name, version, tools })`, преобразование в tool calling Ollama, агентный цикл с `maxTurns`
- [ ] `allowedTools`, `disallowedTools`, `canUseTool`, `permissionMode` и хуки с решениями allow/deny/изменение ввода
- [ ] Контроль размера контекста: SDK сам считает объём входа относительно `num_ctx` и усекает старые результаты инструментов, чтобы Ollama не отбросила вход молча и цикл не упал
- [ ] Дополнить README пакета (инструменты, права, ограничение контекста); тесты первой задачи зелёные

**Когда готова:** Код с `query` + `tool` + `createSdkMcpServer` проходит `tsc` с обоими провайдерами без приведений. Против живой Qwen проходят сценарии с вызовом инструмента, `error_max_turns`, deny в `PreToolUse` и `canUseTool`. Длинная цепочка вызовов не падает при переполнении контекста.

### Фаза 3: Структурированный ответ, стриминг и отмена

**Цель:** SDK возвращает `structured_output` по JSON Schema с проверкой и повторами, отдаёт `stream_event` и останавливается по `interrupt()` и `abortController`.
**Затрагивает:** backend (`packages/llm-sdk`)
**Задачи:**

- [ ] Написать тесты и убедиться, что они красные. Unit на мок-транспорте: `outputFormat: { type: 'json_schema', schema }` → валидный `structured_output`; невалидный ответ повторяется ограниченное число раз, затем `error_during_execution`; `includePartialMessages` даёт `stream_event`; `interrupt()` и `abortController` останавливают генерацию и цикл; `setPermissionMode()` меняет режим во время сессии. Контрактные сценарии: `structured_output`, отмена, `stream_event`. В файл совместимости добавить `outputFormat`
- [ ] `outputFormat` через `format` Ollama, проверка ответа по схеме, ограниченные повторы, `error_during_execution`
- [ ] `includePartialMessages` и `stream_event` из потокового ответа Ollama
- [ ] `interrupt()`, `setPermissionMode()` и `abortController`: отмена текущего HTTP-запроса к Ollama и выход из агентного цикла
- [ ] Дополнить README пакета (структурированный ответ, отмена, отличия от оригинала); тесты первой задачи зелёные

**Когда готова:** Код фичи с `query` + `tool` + `createSdkMcpServer` + `outputFormat` проходит `tsc` с обоими провайдерами без приведений. Против живой Qwen проходят сценарии `structured_output`, `interrupt()`/`abortController` и `stream_event`.

### Фаза 4: Сессии и внешние MCP-серверы

**Цель:** Сессии можно продолжать и ветвить, агент вызывает внешние MCP-серверы. Контрактный набор полный и проходит против обеих реализаций.
**Затрагивает:** backend (`packages/llm-sdk`)
**Задачи:**

- [ ] Написать тесты и убедиться, что они красные. Unit: `resume` продолжает сессию с контекстом, `continue` берёт последнюю сессию, `forkSession` создаёт новую и не меняет исходную, вызов инструмента внешнего stdio-MCP-сервера (тестовый сервер в фикстурах) и сервера по `http`/`sse`. Контрактные сценарии: `resume`, `forkSession`, внешний stdio-MCP
- [ ] Интерфейс хранилища сессий и реализация по умолчанию, опции `resume`, `continue`, `forkSession`
- [ ] Внешние MCP-серверы в `mcpServers`: `stdio` и `http`/`sse`, их инструменты подчиняются тем же правам и хукам, что и SDK-инструменты
- [ ] Прогнать полный контрактный набор против живой Ollama + Qwen и вручную против `@anthropic-ai/claude-agent-sdk` с ключом. Расхождения поведения либо исправить, либо описать в README
- [ ] Завершить README пакета: как поднять Ollama + Qwen + Whisper на второй машине, особенности из PRD, как запускать контрактный набор, требования к проду (бинарник Claude Code, `bypassPermissions`, явные `allowedTools`). Тесты первой задачи зелёные

**Когда готова:** Контрактный набор из «Критериев готовности» PRD целиком проходит против живой Ollama + Qwen и против Claude Agent SDK при ручном запуске с ключом.

### Фаза 5: Саммари встречи по текстовым файлам (API)

**Цель:** Владелец встречи запускает фоновую задачу саммари по текстовым файлам и получает статус и структурированный результат через API.
**Затрагивает:** backend / database
**Задачи:**

- [ ] Написать тесты и убедиться, что они красные. E2E с мок-LLM: запуск, статусы `pending` → `generating` → `done`, результат (`summary`, `decisions[]`, `actionItems[] { task, assignee?, dueDate? }`, `openQuestions[]`, список неучтённых файлов); пересоздание заменяет старое саммари только после успеха; ошибка LLM → `failed` с причиной и успешный повтор; 401 без токена, 404 для чужой встречи, 409 при активной задаче; удаление встречи удаляет саммари. Unit: `read_file` не читает файл чужой встречи, даже если в файле есть инструкция это сделать; таймаут задачи → `failed`; при старте api задачи в `pending`/`generating` помечаются `failed`
- [ ] Модель Prisma саммари (статус, результат, причина ошибки, одна активная задача на встречу) с каскадным удалением вместе со встречей, миграция
- [ ] Модуль `summary` по CQRS: команда запуска и пересоздания с проверкой владельца через `GetMeetingQuery`, запрос статуса и результата, контроллер. Фоновая задача в процессе api с таймаутом на задачу целиком и отменой через `abortController`, пометка зависших задач `failed` при старте
- [ ] Агент на фасаде `@video-meetings/llm`: SDK-сервер с `list_files` и `read_file(fileId, offset, limit)` только по файлам этой встречи и по `fileId` из БД; явные `allowedTools`; источники `.txt`, `.md`, `.vtt`, `.srt`, остальные файлы попадают в список неучтённых; `outputFormat` по JSON Schema; системный промпт с описанием полей и указанием, что содержимое файлов — недоверенный ввод
- [ ] Описать эндпоинты в Swagger, обновить `CLAUDE.md` и `apps/api/CLAUDE.md`; тесты первой задачи зелёные

**Когда готова:** Через API владелец запускает и пересоздаёт саммари встречи с текстовыми файлами, статус доходит до `done`, результат содержит все разделы. Ошибки, 401/404/409, повтор, рестарт api и попытка прочитать чужой файл покрыты тестами.

- [ ] Блок саммари по разделам на HeroUI v3
- [ ] Обновить `apps/web/CLAUDE.md`; тесты первой задачи зелёные

**Когда готова:** Владелец нажимает «Сделать саммари», статус проходит этапы до «Готово» без перезагрузки, на странице видны резюме, решения, задачи и открытые вопросы; при ошибке видна причина и работает повтор.

### Фаза 7: Транскрибация аудио и видео (API)

**Цель:** Аудио- и видеофайлы встречи транскрибируются через Whisper и становятся источниками саммари; повторное саммари использует сохранённый транскрипт.
**Затрагивает:** backend / database
**Задачи:**

- [ ] Написать тесты и убедиться, что они красные. Unit на мок-Whisper: файл передаётся потоком, без чтения в память; ответ whisper.cpp нормализуется (`language` к коду, лишние `tokens`/`words` отброшены); недоступный Whisper даёт понятную ошибку по таймауту. E2E с мок-LLM и мок-Whisper: встреча с аудио проходит статус `transcribing`, саммари учитывает транскрипт; повторный запуск не транскрибирует неизменённый файл; недоступный Whisper → `failed` с причиной и успешный повтор; удаление встречи удаляет транскрипты. Unit агента: транскрипт больше `num_ctx` суммируется, в сообщениях видны многократные вызовы `read_file`
- [ ] Провайдер транскрибации, независимый от `LLM_PROVIDER`: клиент OpenAI-совместимого `/v1/audio/transcriptions` (`WHISPER_URL`, `WHISPER_LANGUAGE`, таймауты), потоковая отправка файлов до 500 МиБ, нормализация ответа, извлечение аудиодорожки из видео, если понадобится
- [ ] Модель Prisma транскрипта с привязкой к файлу встречи, признаком изменения файла и каскадным удалением, миграция
- [ ] Этап `transcribing` в фоновой задаче перед `generating`; `list_files` и `read_file` отдают транскрипты так же, как текстовые файлы, частями
- [ ] Обновить `.env.example` (`WHISPER_URL`, `WHISPER_LANGUAGE`), `CLAUDE.md` и `apps/api/CLAUDE.md`; тесты первой задачи зелёные

**Когда готова:** Встреча с аудио- или видеофайлом получает саммари с учётом транскрипта, повторный запуск не транскрибирует тот же файл заново, транскрипт больше `num_ctx` суммируется через многократные `read_file`, недоступность Whisper даёт `failed` с причиной.
