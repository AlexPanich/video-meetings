# PRD: Локальный LLM SDK, совместимый с Claude Agent SDK, и саммари встречи

**Дата**: 2026-11-12
**Статус**: Draft

## Цель

Нужен пакет `packages/llm-sdk`, который повторяет публичный интерфейс `@anthropic-ai/claude-agent-sdk` и отправляет запросы в модель Qwen. Модель работает в Ollama на отдельной машине в локальной сети. Тогда при разработке и тестах не расходуются платные токены Anthropic, а при выкладке в прод приложение переходит на SDK Anthropic одной настройкой, без правки кода фич. Первая фича на этом SDK — фоновое структурированное саммари встречи по её файлам, включая транскрибацию аудио и видео.

## Пользовательские сценарии

- Разработчик ставит `LLM_PROVIDER=local` и `OLLAMA_URL=http://<ip>:11434` -> все LLM-запросы приложения идут в Qwen на другой машине, к Anthropic не уходит ни одного запроса.
- Разработчик ставит `LLM_PROVIDER=anthropic` и `ANTHROPIC_API_KEY` -> тот же код фич работает через `@anthropic-ai/claude-agent-sdk`.
- Разработчик пишет код с `query()`, `tool()` и `createSdkMcpServer()` по документации Claude Agent SDK -> код работает с обоими провайдерами без условных веток.
- Владелец встречи нажимает «Сделать саммари» на странице встречи -> запускается фоновая задача, на странице виден статус: «В очереди», «Транскрибация», «Генерация», «Готово» или «Ошибка».
- Задача завершилась -> на странице встречи показано саммари: краткое резюме, ключевые решения, задачи (что, кто, срок), открытые вопросы.
- Среди файлов встречи есть аудио или видео -> они транскрибируются, а транскрипт становится одним из источников саммари.
- Транскрипт не помещается в контекст модели -> агент читает файлы частями через инструменты и всё равно выдаёт саммари.
- Владелец нажимает «Пересоздать саммари» -> старое саммари заменяется новым после успешной генерации.
- Машина с Ollama недоступна или генерация упала -> задача получает статус «Ошибка» с понятной причиной, можно повторить.
- Другой пользователь запрашивает саммари чужой встречи -> 404.

## В скоупе

### Пакет `packages/llm-sdk`

- Новый workspace-пакет, ESM. Корневой `pnpm-workspace.yaml` дополнен `packages/*`.
- Экспорты повторяют имена и сигнатуры Claude Agent SDK. Импорт меняется только в одном месте:
  - `query({ prompt, options })` возвращает объект `Query`: это `AsyncGenerator<SDKMessage>` с методами `interrupt()` и `setPermissionMode()`.
  - `prompt` может быть строкой или `AsyncIterable<SDKUserMessage>` (потоковый ввод).
  - `tool(name, description, zodSchema, handler)` и `createSdkMcpServer({ name, version, tools })`.
- Типы сообщений `SDKMessage` повторяют структуру и поля оригинала:
  - `system` (subtype `init`: `session_id`, `model`, `tools`);
  - `assistant` (контент-блоки `text`, `tool_use`);
  - `user` (`tool_result`);
  - `result` (subtypes `success`, `error_max_turns`, `error_during_execution`; поля `result`, `num_turns`, `duration_ms`, `usage`, `total_cost_usd` (для локальной модели 0), `session_id`, `structured_output`);
  - `stream_event` (при `includePartialMessages`).
- Поддерживаемые `options`:
  - `model`, `systemPrompt`, `maxTurns`;
  - `allowedTools`, `disallowedTools`;
  - `mcpServers`: SDK-серверы в процессе плюс внешние MCP-серверы через `stdio` и `http`/`sse`;
  - `canUseTool`, `permissionMode` (`default`, `acceptEdits`, `bypassPermissions`, `plan`);
  - `hooks`: `PreToolUse`, `PostToolUse`, `UserPromptSubmit`, `Stop`, `SessionStart`, `SessionEnd` с matcher и решениями allow/deny/изменение ввода;
  - сессии: `resume`, `continue`, `forkSession`;
  - `abortController`, `includePartialMessages`;
  - `outputFormat: { type: 'json_schema', schema }`, результат в `structured_output`.
- Агентный цикл: модель вызывает инструмент, SDK его выполняет и возвращает результат модели. Цикл идёт, пока модель не даст финальный ответ или не будет достигнут `maxTurns`. Имена MCP-инструментов в формате `mcp__<server>__<tool>`, как в оригинале.
- Транспорт — Ollama (Qwen с поддержкой tool calling, например Qwen3). URL, модель и таймауты задаются через env.
- Хранение сессий для `resume`/`continue`/`forkSession`: интерфейс хранилища плюс реализация по умолчанию.
- Фасад `@video-meetings/llm` (или модуль в api): выбирает реализацию по `LLM_PROVIDER` (`local` | `anthropic`) и реэкспортирует единый набор функций и типов. Код фич импортирует только фасад.
- Контрактный набор тестов на сценарии из «Критериев готовности». Он прогоняется против обеих реализаций; против Anthropic — только вручную, по флагу.

### Транскрибация

- Аудио- и видеофайлы встречи транскрибируются сервисом на машине с Ollama: Whisper-сервер с OpenAI-совместимым `/v1/audio/transcriptions`.
- Транскрипт хранится и переиспользуется: повторное саммари не транскрибирует файл заново, пока он не изменился.
- Транскрибация — отдельный провайдер, а не часть SDK. В Claude Agent SDK её нет, поэтому переключение `LLM_PROVIDER` её не затрагивает. URL задаётся через свою env-переменную.

### Саммари встречи (apps/api + apps/web)

- Источники: текстовые файлы (`.txt`, `.md`, `.vtt`, `.srt`) и транскрипты аудио и видео. Остальные типы пропускаются, в саммари указано, какие файлы не учтены.
- Агент получает инструменты `list_files` и `read_file(fileId, offset, limit)` только по файлам этой встречи и читает их частями.
- Формат результата задаётся JSON Schema через `outputFormat`: `summary`, `decisions[]`, `actionItems[] { task, assignee?, dueDate? }`, `openQuestions[]`.
- Фоновая задача со статусами `pending`, `transcribing`, `generating`, `done`, `failed`. Одна активная задача на встречу. Статус и результат хранятся в БД.
- API (только владелец встречи): запустить или пересоздать саммари, получить статус и результат. Эндпоинты описаны в Swagger.
- UI на странице встречи: кнопка запуска и пересоздания, отображение статуса с обновлением, блок саммари по разделам, текст ошибки и повтор.
- Удаление встречи удаляет её саммари и транскрипты.
- Unit-тесты SDK и модуля саммари на мок-транспорте, e2e api с мок-LLM, тесты UI.
- Обновление `CLAUDE.md`, `apps/api/CLAUDE.md`, `.env.example`, README пакета (как поднять Ollama + Qwen + Whisper на второй машине).

## Не в скоупе

- Встроенные инструменты Claude Code (`Read`, `Write`, `Bash`, `Grep`, `WebSearch` и т. п.), субагенты (`agents`), slash-команды, `settingSources`/`CLAUDE.md`, плагины. Фичи приложения их не используют, а в проде они опасны.
- Другие провайдеры (OpenAI, vLLM, LM Studio), кроме Ollama и Anthropic.
- Мультимодальность: изображения, PDF и DOCX.
- Реальный подсчёт стоимости для локальной модели.
- Стриминг саммари в UI по мере генерации.
- Диаризация (кто говорит) в транскрипте.
- Редактирование саммари пользователем, экспорт, отправка участникам.
- Очередь задач на отдельном сервисе (Redis/BullMQ). Фоновые задачи работают внутри процесса api.
- Авторизация и TLS между api и машиной с Ollama: считаем сеть доверенной.

## Инфраструктура разработки (настроена 2026-11-12)

Вторая машина в LAN: Windows 11, RTX 5080 16 ГБ. Доступ только с машины разработчика (правила файрвола по IP, профиль Private).

| Сервис                                                                               | Адрес                                                 | Что работает                                                                                                                                                                |
| ------------------------------------------------------------------------------------ | ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ollama 0.40.16 (`ollama serve`, ctx 32768, flash attention, KV q8_0, keep-alive 30m) | `http://192.168.100.204:11434`                        | `qwen3:14b` Q4_K_M, 100% GPU (11,9 ГБ); tool calling, `format` по JSON Schema, `/v1/chat/completions`, `think` on/off per-request; ~82 tok/s генерация, ~3000 tok/s prefill |
| whisper.cpp v1.9.5 CUDA (`whisper-server`, `--convert`)                              | `http://192.168.100.204:8000/v1/audio/transcriptions` | `large-v3-turbo-q8_0`, GPU; wav и mp4; `json`/`verbose_json` с сегментами; ~40–95× реального времени                                                                        |

Значения для `.env.example`:

```
LLM_PROVIDER=local
OLLAMA_URL=http://192.168.100.204:11434
OLLAMA_MODEL=qwen3:14b
OLLAMA_NUM_CTX=32768
WHISPER_URL=http://192.168.100.204:8000
WHISPER_LANGUAGE=ru
```

Обнаруженные особенности, которые SDK и транскрибация должны учитывать:

- При переполнении `num_ctx` Ollama **молча** отбрасывает часть входа (ошибки нет, ответ становится неверным). SDK должен сам контролировать размер контекста.
- Ответ по схеме валиден структурно, но поля заполняются неточно (задачи попадали в `decisions`, `actionItems` пустой): нужен системный промпт с описанием полей.
- Ответ whisper.cpp отличается от OpenAI: `language` — полное имя (`"russian"`, а не `"ru"`), поле `model` игнорируется, в сегментах есть лишние `tokens`/`words`. Клиент транскрибации нормализует ответ.
- VRAM при одновременной работе Qwen и Whisper: ~15,0 из 16,3 ГБ — запаса почти нет; модель крупнее 14b рядом с Whisper не поместится.
- Сервисы стартуют только после входа пользователя в Windows; при недоступности клиент должен давать понятную ошибку, а не зависать.

## Технические ограничения

- **Совместимость — главное требование.** Совпадение проверяется по типам: код фич компилируется с обоими провайдерами без `any` и приведений. Опорная версия `@anthropic-ai/claude-agent-sdk` фиксируется в `package.json`. Отличия поведения перечислены в README пакета.
- Claude Agent SDK запускает Claude Code как дочерний процесс. Для прода нужен бинарник на сервере, а `bypassPermissions` и отключение встроенных инструментов обязательны для серверного использования. Код фич должен явно задавать `tools: []` (отключает встроенные инструменты) и `allowedTools`, чтобы прод-агент не получил доступ к файловой системе и shell сервера: в Claude Agent SDK `allowedTools` — только список автоодобрения, набор инструментов он не ограничивает.
- Qwen слабее Claude в tool calling и строгом JSON. SDK должен валидировать `structured_output` по схеме и при невалидном ответе повторять попытку ограниченное число раз, после чего возвращать `error_during_execution`.
- Контекст Qwen в Ollama ограничен `num_ctx`. Значение настраивается, а агентный цикл не должен падать при переполнении: старые результаты инструментов усекаются.
- Генерация на локальной машине может идти минутами. Нужны таймауты на запрос и на задачу целиком, отмена через `abortController`, а при рестарте api зависшие задачи помечаются `failed`.
- Аудио и видео до 500 МиБ передаются на транскрибацию потоком, без загрузки в память api. Для видео может понадобиться извлечение аудиодорожки.
- Доступ агента к файлам — только к файлам своей встречи, по `fileId` из БД, не по путям (защита от path traversal и утечки чужих данных через prompt injection в файлах).
- Содержимое файлов — недоверенный ввод: инструкции внутри транскрипта не должны менять права агента.
- api — нативный ESM, CQRS, Prisma 7, глобальный `ValidationPipe`; новый пакет подключается так, чтобы `pnpm build`/`test`/`lint` работали из корня.
- Unit-тесты и pre-commit hook не должны требовать Ollama или сети.

## Критерии готовности

- [ ] `packages/llm-sdk` собирается, подключён в workspace, `pnpm build`, `pnpm lint` и `pnpm test` проходят из корня.
- [ ] Один и тот же код фичи (`query` + `tool` + `createSdkMcpServer` + `outputFormat`) проходит `tsc` с обоими провайдерами без приведений типов.
- [ ] Против живой Ollama + Qwen контрактный набор проходит: простой ответ, вызов SDK-инструмента и результат, `maxTurns` → `error_max_turns`, `structured_output` по схеме, `interrupt()`/`abortController` останавливает генерацию, `resume` продолжает сессию с контекстом, `forkSession` не меняет исходную сессию, хук `PreToolUse` с deny блокирует инструмент, `canUseTool` с deny блокирует инструмент, `includePartialMessages` даёт `stream_event`, внешний stdio-MCP-сервер вызывается.
- [ ] Тот же набор проходит против `@anthropic-ai/claude-agent-sdk` при ручном запуске с ключом.
- [ ] При `LLM_PROVIDER=local` не уходит ни одного запроса на домены Anthropic (проверено тестом с перехватом сети).
- [ ] Переключение на Anthropic делается только сменой env, без изменений кода.
- [ ] Владелец встречи запускает саммари, статус проходит этапы до `done`, на странице видны резюме, решения, задачи и открытые вопросы.
- [ ] Встреча с аудио- или видеофайлом получает саммари с учётом транскрипта; повторный запуск не транскрибирует тот же файл заново.
- [ ] Транскрипт больше `num_ctx` модели успешно суммируется, а в логах сообщений видны многократные вызовы `read_file`.
- [ ] Недоступность Ollama или Whisper даёт статус `failed` с причиной, повтор работает; после рестарта api нет задач, навсегда зависших в `generating`.
- [ ] Запросы без токена — 401, к чужой встрече — 404, повторный запуск при активной задаче — 409; покрыто e2e.
- [ ] Агент не может прочитать файл чужой встречи, даже если в транскрипте есть инструкция сделать это (тест).
- [ ] Эндпоинты описаны в Swagger, `pnpm test:e2e` проходит.
- [ ] `CLAUDE.md`, `apps/api/CLAUDE.md`, `.env.example` и README пакета обновлены, включая инструкцию по настройке второй машины.
