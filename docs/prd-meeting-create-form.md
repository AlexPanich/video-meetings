# PRD: Форма создания встречи

**Дата**: 2026-11-18
**Статус**: Draft

## Цель

Дать пользователю создать встречу из интерфейса. Сейчас кнопка «Создать встречу» на главной ничего не делает, и встречу можно создать только прямым запросом к API, а без встречи нельзя загрузить материалы и получить саммари.

## Пользовательские сценарии

- Пользователь нажимает «Создать встречу» на главной -> открывается модальное окно с полями «Название», «Дата», «Время» и «Участники»; дата и время заполнены текущим днём и ближайшим следующим целым часом.
- Пользователь вводит название, выбирает дату и время и нажимает «Создать» -> встреча создаётся, окно закрывается, открывается страница новой встречи `/meetings/:id`.
- Пользователь вводит имя участника и нажимает Enter или запятую -> имя становится тегом в поле «Участники», поле ввода очищается.
- Пользователь нажимает крестик на теге или Backspace в пустом поле ввода -> участник удаляется из списка.
- Пользователь вводит имя, которое уже есть в списке (без учёта регистра и пробелов по краям) -> второй тег не появляется.
- Пользователь вписал имя, но не превратил его в тег, и нажал «Создать» -> вписанное имя добавляется в участники.
- Пользователь создаёт встречу без участников -> встреча создаётся с пустым списком участников.
- Пользователь оставляет название пустым или из одних пробелов -> встреча не создаётся, у поля показывается ошибка.
- Пользователь вводит слишком длинное название или имя участника, или превышает число участников -> встреча не создаётся, показывается сообщение с причиной.
- Пользователь нажимает «Отмена», Esc или кликает вне окна -> окно закрывается, встреча не создаётся; при следующем открытии форма пустая.
- API отвечает ошибкой или недоступен -> окно остаётся открытым, введённые данные сохраняются, показывается сообщение об ошибке.
- Пользователь нажимает «Создать» несколько раз подряд -> создаётся одна встреча.
- Пользователь возвращается на главную после создания -> новая встреча есть в «Последних встречах», счётчик встреч увеличен.
- Сессия пользователя истекла к моменту отправки -> пользователь переходит на страницу входа.

## В скоупе

- Модальное окно создания встречи, открывается кнопкой «Создать встречу» на главной.
- Поле «Название»: обязательное, после обрезки пробелов от 1 до 200 символов, без управляющих символов.
- Поля «Дата» и «Время»: обязательные, по умолчанию сегодня и ближайший следующий целый час; время берётся в часовом поясе браузера. Прошедшие и будущие даты допускаются.
- Поле «Участники»: необязательное, ввод имён тегами (Enter или запятая), удаление крестиком и Backspace; имя после обрезки пробелов от 1 до 100 символов, без управляющих символов; не больше 50 участников; повторы без учёта регистра не добавляются.
- Кнопка «Создать» блокируется и показывает загрузку на время запроса.
- Переход на страницу созданной встречи после успеха.
- Актуальные счётчик и «Последние встречи» на главной после создания.
- Те же ограничения названия, участников и даты на стороне API (`POST /meetings`): нарушение — 400 с понятным сообщением; пробелы по краям названия и имён обрезаются, повторяющиеся участники убираются.
- Обновление описания `POST /meetings` в Swagger.
- Тесты UI формы, unit- и e2e-тесты валидации API.
- Обновление документации (`CLAUDE.md`, `apps/api/CLAUDE.md`, `apps/web/CLAUDE.md`) в рамках изменения.

## Не в скоупе

- Редактирование существующей встречи.
- Отдельная страница создания встречи и кнопки создания на других страницах.
- Загрузка файлов прямо в форме создания.
- Подсказки участников из прошлых встреч или из пользователей системы, email участников, приглашения и уведомления.
- Длительность встречи, повторяющиеся встречи, выбор часового пояса.
- Черновики формы между открытиями.
- Страница со списком всех встреч.

## Технические ограничения

- Браузер не видит JWT: запрос идёт через BFF (route handlers Next.js в `apps/web/src/app/api`), 401 от API должен приводить к переходу на `/login`, как в остальных формах.
- API принимает дату в ISO 8601 и хранит её в UTC; форма переводит выбранные дату и время из часового пояса браузера, а страница встречи и главная показывают их обратно в локальном времени.
- Сейчас `CreateMeetingDto` проверяет только типы: нет ограничений длины, числа участников и управляющих символов. Встречи, уже созданные с нарушением новых правил, должны и дальше открываться.
- На главной включены `cacheComponents` и `partialPrefetching`, а Next 16 скрывает страницу вместо размонтирования: после создания главная не должна показывать устаревшие счётчик и список.
- UI — HeroUI v3 (модальное окно, поля даты и времени, теги); доступность с клавиатуры: фокус в окне, закрытие по Esc, возврат фокуса на кнопку.
- API — нативный ESM, CQRS, глобальный `ValidationPipe`, Swagger по соглашениям проекта.

## Критерии готовности

- [ ] Кнопка «Создать встречу» на главной открывает модальное окно с полями «Название», «Дата», «Время», «Участники»; дата и время по умолчанию — сегодня и ближайший следующий целый час.
- [ ] Заполненная форма создаёт встречу, окно закрывается, браузер оказывается на `/meetings/:id` новой встречи с введёнными названием, датой, временем и участниками.
- [ ] Встреча, созданная на 15:00 по времени браузера, показывается на странице встречи и на главной как 15:00.
- [ ] Встреча без участников создаётся; на её странице список участников пуст.
- [ ] Enter и запятая превращают введённое имя в тег; крестик и Backspace в пустом поле удаляют тег; повтор имени без учёта регистра тег не добавляет; невписанное в тег имя попадает в участники при отправке.
- [ ] Пустое название, название из пробелов, длиннее 200 символов или с управляющими символами не отправляется; у поля показывается ошибка.
- [ ] Имя участника длиннее 100 символов или с управляющими символами не добавляется; 51-й участник не добавляется; пользователь видит причину.
- [ ] Прямой запрос к `POST /meetings` с нарушением любого из правил названия, участников или даты получает 400; пробелы по краям обрезаются, повторы участников убираются в сохранённой встрече.
- [ ] Повторные нажатия «Создать» во время запроса создают одну встречу.
- [ ] При ошибке API окно остаётся открытым, введённые данные сохраняются, показывается сообщение.
- [ ] «Отмена», Esc и клик вне окна закрывают его без создания встречи; при следующем открытии форма пустая.
- [ ] После создания и возврата на главную счётчик увеличен, новая встреча есть в «Последних встречах» без ручной перезагрузки.
- [ ] Отправка формы с истёкшей сессией приводит на `/login`.
- [ ] Окно полностью управляется с клавиатуры: фокус внутри окна, Esc закрывает, фокус возвращается на кнопку «Создать встречу».
- [ ] Ограничения `POST /meetings` описаны в Swagger (`/docs`).
- [ ] `pnpm lint`, `pnpm test` и `pnpm test:e2e` проходят.
