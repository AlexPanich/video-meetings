# PRD: Профиль пользователя

**Дата**: 2026-11-03
**Статус**: Draft

## Цель

Дать пользователю возможность посмотреть свои данные и управлять ими: изменить имя, загрузить или удалить аватар, сменить пароль. Аватар помогает сразу увидеть, под каким аккаунтом выполнен вход, а смена пароля позволяет защитить аккаунт, если пароль мог стать известен другим.

## Пользовательские сценарии

- Пользователь нажимает на аватар в блоке приветствия на главной -> открывается страница профиля с аватаром, именем и email.
- Пользователь нажимает «Редактировать» на странице профиля -> открывается страница редактирования.
- Пользователь меняет имя и сохраняет -> новое имя показывается в профиле и на главной.
- Пользователь отправляет пустое имя или имя из одних пробелов -> имя не меняется, показывается сообщение об ошибке.
- Пользователь загружает изображение JPG, PNG или WebP размером до 5 МБ -> аватар заменяется в профиле и на главной, прежнее изображение удаляется из хранилища.
- Пользователь выбирает файл другого формата или больше 5 МБ -> текущий аватар не меняется, показывается сообщение с причиной.
- Пользователь удаляет аватар и подтверждает действие -> изображение удаляется из хранилища, в профиле и на главной показываются инициалы из имени.
- Пользователь без аватара открывает профиль или главную -> видит инициалы из имени.
- Пользователь вводит верный текущий пароль и новый пароль с повтором -> пароль меняется, текущая сессия остаётся активной, другие сессии завершаются.
- Пользователь вводит неверный текущий пароль -> пароль не меняется, показывается сообщение об ошибке.
- Пользователь вводит новый пароль короче 8 символов, совпадающий с текущим или не совпадающий с повтором -> пароль не меняется, показывается сообщение об ошибке.
- Пользователь выполняет запрос из другой сессии после смены пароля -> получает отказ и переходит на страницу входа.
- Гость открывает страницу профиля или редактирования -> переходит на страницу входа.

## В скоупе

- Страница профиля `/profile`: аватар или инициалы, имя, email, кнопка «Редактировать».
- Страница редактирования `/profile/edit`: изменение имени, загрузка, замена и удаление аватара, смена пароля. Каждое из этих действий выполняется независимо от остальных.
- Аватар в блоке приветствия на главной странице: ссылка на страницу профиля.
- Аватар: форматы JPG, PNG, WebP, размер до 5 МБ, у пользователя не больше одного аватара.
- Смена пароля: текущий пароль, новый пароль, повтор нового пароля. Новый пароль содержит минимум 8 символов и отличается от текущего.
- Завершение других сессий пользователя при смене пароля.
- API для получения и изменения профиля, загрузки и удаления аватара, смены пароля. Только для авторизованных; доступны только собственные данные.
- Описание новых эндпоинтов в Swagger.
- Unit- и e2e-тесты API, тесты UI.
- Обновление документации (`CLAUDE.md`, `apps/api/CLAUDE.md`, `apps/web/CLAUDE.md`, `.env.example`) в рамках изменения.

## Не в скоупе

- Смена email и его подтверждение.
- Восстановление забытого пароля.
- Удаление аккаунта.
- Просмотр списка сессий и выборочное завершение сессий.
- Кадрирование, редактирование и генерация уменьшенных копий аватара.
- Показ аватаров других пользователей, профили других пользователей.
- Общая шапка и новая навигация по приложению.
- Ограничение числа попыток ввода текущего пароля.
- Облачное/S3-хранилище.

## Технические ограничения

- Сейчас JWT не отзываются и действуют до истечения срока (`JWT_EXPIRES_IN`, по умолчанию 1 час). Завершение других сессий требует, чтобы API отклонял токены, выданные до смены пароля, а текущая сессия должна остаться рабочей.
- JWT остаётся в HttpOnly-cookie и не попадает в браузер; запросы браузера идут через BFF на route handlers Next.js.
- `src/proxy.ts` защищает только перечисленные маршруты, поэтому `/profile` и `/profile/edit` нужно закрыть явно.
- Формат аватара проверяется на сервере по содержимому файла, а не только по расширению и заявленному MIME-типу; SVG не принимается.
- Лимит 5 МБ проверяется и на клиенте, и на сервере, независимо от лимита файлов встреч (`MAX_UPLOAD_BYTES`).
- Аватары хранятся на локальном диске под сгенерированными именами, исходное имя файла в путях не используется.
- Сбой при замене или удалении не должен оставлять пользователя с записью об аватаре, файла которого нет в хранилище.
- Страницы используют `cacheComponents` и `partialPrefetching`, а Next 16 скрывает страницу вместо размонтирования: после изменений профиль и главная не должны показывать устаревшие имя и аватар.
- API — нативный ESM, CQRS (команды/запросы через шины), валидация и Swagger по существующим соглашениям проекта. UI — HeroUI v3.

## Критерии готовности

- [ ] Гость при открытии `/profile` и `/profile/edit` попадает на `/login`; запросы к API профиля без токена получают 401.
- [ ] `/profile` показывает аватар или инициалы, имя и email текущего пользователя; кнопка «Редактировать» ведёт на `/profile/edit`.
- [ ] Клик по аватару в блоке приветствия на главной ведёт на `/profile`.
- [ ] После сохранения имени новое значение показывается на `/profile` и на главной без ручной перезагрузки страницы; пустое имя и имя из пробелов отклоняются с сообщением.
- [ ] Файлы JPG, PNG и WebP размером до 5 МБ принимаются как аватар; после загрузки новый аватар показывается на `/profile` и на главной без ручной перезагрузки.
- [ ] Файл больше 5 МБ отклоняется и на клиенте, и при прямом запросе к API (413).
- [ ] Файл другого формата, включая SVG и файл с подменённым расширением или MIME-типом, отклоняется при прямом запросе к API; текущий аватар при этом не меняется.
- [ ] После замены или удаления аватара прежний файл отсутствует на диске.
- [ ] Удаление аватара требует подтверждения; после него на `/profile` и на главной показываются инициалы.
- [ ] Смена пароля с неверным текущим паролем, новым паролем короче 8 символов, новым паролем, совпадающим с текущим, или расхождением с повтором не меняет пароль; пользователь видит сообщение с причиной.
- [ ] После успешной смены пароля вход возможен только с новым паролем, текущая сессия продолжает работать.
- [ ] Токен, выданный до смены пароля в другой сессии, получает 401 от API; такая сессия в браузере переходит на `/login`.
- [ ] Ни один ответ API профиля не содержит хеш пароля.
- [ ] Пользователь через API профиля не может прочитать или изменить данные другого пользователя.
- [ ] Новые эндпоинты описаны в Swagger (`/docs`).
- [ ] `pnpm lint`, `pnpm test`, `pnpm test:e2e` и `pnpm --filter web typecheck` проходят; новые сценарии покрыты тестами API и UI.
- [ ] Документация и `.env.example` обновлены.
